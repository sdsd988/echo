## S1 — Plan Mode로 timeline 설계 (코드 X, 계획만)

먼저 **`Shift+Tab`을 눌러 Plan Mode로 전환**하세요(권한 모드 사이클). 이 모드에선 Claude가 파일을 못 바꾸고 *계획만* 냅니다. 그 상태에서:

```
타임라인 기능을 추가하려고 해. modules/timeline 모듈을 새로 만들어서
최신순 피드를 조립하는 골격을 세우고 싶어. 바로 코드 짜지 말고 계획부터 세워줘.
제약은 .claude/rules를 따라:
- 모듈 간 직접 의존 금지 — timeline은 post 모듈을 import하면 안 돼. 글 데이터는 앱 계층(customer-api)이 PostService에서 받아 넘기는 구조로.
- 도메인/application은 Spring Web 의존 없음, HTTP는 apps/customer-api.
새 모듈이니 settings.gradle.kts include와 EchoApplication 스캔 등록(scanBasePackages)까지 계획에 포함해줘.
```

> 계획에 *모듈 생성 + settings.gradle include + EchoApplication 스캔 등록 + 앱 계층 조립*이 다 들어왔는지 보세요. 빠지면 빌드가 깨집니다 — 그래서 계획 단계에서 잡는 겁니다.

## S3 — /permissions로 위험 명령 게이트 깔기

앞으로 위험한 명령(7장 DB 마이그레이션·삭제 등)에 대비해 **권한 게이트**를 둡니다. `.claude/settings.json`에 규칙을 적으면 도구 호출 직전에 걸러집니다.

```
.claude/settings.json에 권한 규칙을 추가해줘. Deny > Ask > Allow 순으로 평가되고
먼저 매칭되는 규칙이 이긴다는 점 반영해서:
- deny: rm -rf 류, .env 읽기
- ask: git push, psql, docker
- allow: ./gradlew build / test / bootRun
```

> 시연 팁: deny에 걸리는 명령(예: `rm -rf` 비슷한 걸 시켜보기)을 한 번 줘보면 게이트가 실제로 막는 걸 보여줄 수 있습니다.

## 끝난 뒤 확인

- `modules/timeline` 생성 — `FeedItem`(domain record), `TimelineService.assemble`(application, `@Service`). **post를 import하지 않음**
- `apps/customer-api`에 `TimelineController` (`GET /timeline`) — `PostService`로 글을 받아 `TimelineService`에 넘겨 조립(앱이 모듈을 조립)
- `settings.gradle.kts`에 `include("modules:timeline")`, `EchoApplication` `scanBasePackages`에 `com.echo.timeline.application` 추가
- `.claude/settings.json` 권한 규칙(deny/ask/allow) 생성
- `.claude/rules/timeline.md` (paths 스코프) 생성
- `./gradlew build` 통과, `GET /timeline` 최신순 응답

> 다 끝내면 이 상태가 `v4.4-baseline`입니다. 막히면 `git checkout v4.4-baseline`으로 정답과 비교하세요.
