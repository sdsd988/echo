## 이번 편 요구사항 — 새 기능 없음, echo 출시 전 종합 QA

이번 편은 새 모듈을 만들지 않습니다. 그동안 쌓인 echo 전체를 **출시 전에 팀으로 종합 검수**합니다.

- **대상:** 그동안 쌓인 코드 — `follow`·`engagement`·`moderation` 모듈, MCP 설정(`.mcp.json`), 테스트.
- **방식:** **보안·성능·테스트 세 관점**을 팀원에게 **동시에** 맡겨 같은 코드를 읽히고, **리드가 심각도 순으로 하나로 종합**.
- **재사용:** 보안 관점은 실습-서브에이전트에서 만든 **`echo-security-reviewer`** 서브에이전트를 **팀원으로 재사용**.

> Agent Teams는 **실험 기능**입니다 — 기본으로 꺼져 있어 S0에서 켭니다. 같은 코드를 *읽기만* 하는 리뷰라, 작업 충돌·순서 의존이 없어 팀을 붙이기 가장 깔끔한 일입니다.

## S0 — Agent Teams 켜기

실험 기능이라 환경변수 하나로 켭니다. settings.json에 박아 두면 이 프로젝트에선 계속 켜집니다.

```
이 프로젝트에서 Agent Teams를 켜고 싶어.
.claude/settings.json의 env 블록에 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS를 "1"로 추가해줘.
그리고 claude --version으로 버전이 2.1.32 이상인지 확인해줘.
```

### 끝난 뒤 확인

- `.claude/settings.json`에 `env` 블록과 `"CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"`이 생겼는지 확인.
- settings.json을 바꿨으니 **세션을 다시 띄워야** 적용됩니다.
- 지난 편 인프라(Postgres)가 살아 있는지 한 번 확인:

```
docker compose up -d
```

> **짚기.** 켜는 스위치는 환경변수 하나(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`). 셸에 `export`하면 "이번 세션만", settings.json `env` 블록에 넣으면 "이 프로젝트 계속". 실험 기능이라 세션 되살리기에 약하고 작업 상태 갱신이 늦을 수 있다는 점은 알고 들어갑니다.

## S1 — QA 리뷰 팀 꾸려 echo 종합 리뷰

리드(메인 세션)에게 **자연어로** 팀을 부탁합니다. 팀원을 손으로 만들지 않습니다 — 리드가 알아서 띄우고, 쪼개 배정하고, 종합합니다.

```
echo를 출시 전에 팀으로 종합 리뷰해 줘.
- 보안 관점은 지난번에 만든 echo-security-reviewer 서브에이전트를 팀원으로 재사용해 줘.
- 성능 관점(불필요한 DB 왕복·N+1 같은 것), 테스트 관점(경계값·실패 케이스 커버리지)은
  각각 팀원을 하나씩 띄워서 맡겨 줘.
- 셋이 같은 코드(follow·engagement·moderation·MCP 설정)를 동시에 보고,
  리드가 세 리뷰를 모아 심각도 순으로 하나로 종합해 줘.
```

> `echo-security-reviewer`는 지난 편에서 만든 이름입니다. 다른 이름으로 만들었다면 그 이름으로 바꿔 지목하세요.

### 끝난 뒤 확인

- 리드가 **공유 Task List**에 리뷰 task 세 개(보안·성능·테스트)를 올리고, 팀원 셋이 병렬로 코드를 읽습니다.
- 셋이 끝나면 리드가 **심각도 순 종합 리뷰** 한 장을 돌려줍니다. (코드 파일은 안 바뀝니다 — 읽고 지적만.)

> **짚기.**
> - **서브에이전트 정의 재사용** — `echo-security-reviewer`를 이름으로 지목하면 팀원으로 와도 정의의 `tools`(Write·Edit 없음 = 코드 못 고침)·`model`(opus)을 그대로 따릅니다. 단, 정의의 `skills`·`mcpServers`는 팀원엔 안 따라오고 프로젝트·사용자 설정에서 로드됩니다.
> - **읽기만 하니 깔끔** — 같은 코드를 셋이 동시에 봐도 덮어쓸 일도, 순서 기다릴 일도 없습니다. worktree도 필요 없습니다.
> - **사각지대↓·속도↑** — 한 관점은 자기 관심사로 쏠립니다. 셋이 다른 렌즈로 동시에 보면 골고루 걸러지고, 순차로 보는 것보다 빠릅니다.
> - **공유 Task List** — 세 리뷰가 pending→in progress→completed로 한 판에. 팀원은 빈 작업을 스스로 집어 들고(self-claim), 각자 독립 컨텍스트에서 일합니다.
> - **비용·인원** — 팀원 하나가 별도 Claude라 토큰이 곱으로 듭니다. 갈라 검수할 만큼 코드가 넓게 퍼졌을 때만. 실전 인원은 3~5가 출발점.

## S2 — 종합 결과 정리 (선택)

리드가 돌려준 종합 리뷰를 파일로도 남깁니다.

```
리드가 종합한 리뷰를 docs/qa-report.md로 정리해 줘 — 심각도·관점(보안/성능/테스트)·파일 위치별로.
```

### 끝난 뒤 확인

- `docs/qa-report.md`에 심각도·관점·위치별 리뷰가 정리됩니다.
- 리드 화면(in-process 한 화면 순회)에서 팀원 패널을 **화살표로 고르고 Enter로** 각 팀원 작업을 펼쳐 볼 수 있습니다. 이름으로 직접 추가 질문도 가능합니다(팀원은 리드 대화 이력을 모르니 맥락을 담아서).

> **짚기.**
> - **관측성** — 팀원이 여럿 동시에 돌면 "누가 어디까지"를 보는 게 중요해집니다. 리드 현황판이 그 역할입니다.
> - **서브에이전트 vs 팀** — 서브에이전트는 혼자 일하고 메인에만 보고. 팀은 같은 코드를 여럿이 동시에 다른 렌즈로 보고, 리드 현황판·종합이 붙습니다. (팀원 간 직접 통신은 *서로 맞춰 만들 때* 쓰는데, 순수 리뷰엔 필요 없습니다.)
> - **정리는 자동** — 팀은 손으로 해체하지 않습니다. 세션이 끝나면 자동 정리됩니다.
